## この資料の範囲と読み方

- 対象はココロネAI for DesktopのWindows版。Web版の機能一覧ではない。
- 画面だけでなく、React/TypeScript、Windowsホスト、C#共通処理、保存・通信経路を読み合わせて作成した。
- **「実装」はソースに処理があるという意味**。今回、アプリ起動、テスト、モデル生成、録音、外部サービスへの接続は実施していない。全環境での動作保証や、公開済み配布物の検収結果ではない。
- 見出しに指定がなければソース上の実装項目。外部サービス・機器・追加エンジン・対応モデルが必要なものは条件を併記した。
- **「未接続」「表示用」「開発中」も末尾に収録**した。コードや説明が残っているだけのものを、利用可能な機能に数えていない。
- ロードマップの実装案をそのまま現行機能に転記していない。特にセットアップの古い「機能状態」説明と、現在の実装には食い違いがある。
- 個人の会話・通常プロファイル・APIキー・秘密情報を含めず、機能と利用条件を整理した。
- 以下は利用者の操作と動作を細分化した目録。同じ処理の入口が複数ある場合は、入口ごとの差も記載している。

## 1. アプリ全体・起動・Windows連携

### 1.1 アプリとウィンドウ

- Windowsデスクトップアプリとして起動する。
- WPFホスト内のWebView2に、同梱された画面を表示する。
- Web版の開発サーバーを起動しなくても、アプリ内画面を利用する。
- 本体の最小化・最大化・復元・終了操作。
- Windowsの作業領域に合わせた初期ウィンドウサイズ調整。
- 保存したウィンドウ配置・ペイン状態の利用。
- 本体、セットアップ、Mini Chat、Mini Dock、常駐バー、メディアブラウザーを用途別のウィンドウとして扱う。
- ロゴを使った起動アニメーション。
- 起動時の言語とライト/ダーク設定を、画面の準備前から起動表示に反映する。
- アプリの版をα版として表示する。
- 保存先ごとの単一インスタンス制御。
- 二度目の起動要求を既存インスタンスへ渡す。
- `--data-dir` で独立したデータ保存先を指定できる。
- 通常利用の保存先とテスト用保存先を分離できる。
- 画面表示エンジンが異常終了した場合の案内。
- レンダラ停止時、一度の自動再読み込みによる復帰を試みる。
- 短時間で停止が繰り返された場合、再読み込みを無限に続けず再起動を案内する。
- UI例外用のエラーバウンダリーとエラー記録。

### 1.2 通知領域・タスクバー

- 閉じるボタンで本体を隠し、通知領域で動作を続ける設定。
- 常駐中の回答生成・バックグラウンド作業の継続。
- 通知領域メニューから本体を開く。
- 通知領域アイコンのダブルクリックで本体を表示する。
- 通知領域からMini Chatを開閉する。
- 通知領域からMini Dockを開く。
- 通知領域からAI接続設定を開く。
- 通知領域からAPIキー変更を開く。
- 通知領域から完全終了する。
- 完了などのWindows通知。
- 通知を押して対象の作業や会話へ移動する。
- タスクバーのジャンプリストから新しい会話を開始する。
- ジャンプリストからMini Chatを開く。
- ジャンプリストからMini Dockを開く。
- ジャンプリストからタイマーを開く。
- コーディング実行中はタスクバーボタンに不定進捗を表示する。
- 承認待ちではタスクバー進捗を待機色にする。
- 承認待ちを、キーボードフォーカスを奪わずタスクバー点滅で知らせる。
- Windowsサインイン時の自動起動をオン/オフにする。
- 自動起動時、常駐設定に応じて通知領域へ静かに起動する。

### 1.3 Windowsからの入力・外部アプリ

- 起動引数で受け取ったローカルファイルを、チャット入力欄へ追加する。
- 起動時ファイルは自動でAI送信せず、送信前の添付として扱う。
- この経路では1ファイル32MBを超える場合に案内を出す。
- 保存ダイアログを使ったファイル書き出し。
- ファイル/フォルダー選択ダイアログ。
- エクスプローラーで対象ファイルを表示する。
- 許可されたファイルをWindows既定アプリで開く。
- 外部Webリンクを既定ブラウザーで開く。
- コマンドパレットからスタートメニューのアプリを検索する。
- アプリ名をひらがな・半角等でも探しやすくする正規化。
- 一覧にあるアプリを選んで起動する。
- 任意文字列をそのまま実行するのではなく、検出したアプリIDを起動に使う。

### 1.4 コマンドパレット・ヘルプ

- アプリの操作を検索窓から探す。
- 操作名/キーワード/カテゴリで絞り込む。
- 新規会話/会話内検索/数学切替へ移動する。
- ライブラリ/プロジェクト/成果物/プロンプト/メモリー/意味検索へ移動する。
- Activity/道具/音声メモ/費用とプライバシー/調査/信頼性へ移動する。
- モデル比較/ツール設定/設定/インポート/エクスポートを呼び出す。
- アプリ名入力時はWindowsアプリの起動候補も追加する。
- 上下キーで候補を移動する。
- Enterで選んだ操作を実行する。
- Esc/閉じる/背景クリックで閉じる。
- 一致しない場合の空表示。
- 使い方ガイドを開閉する。
- ガイドには一部Web版の古い説明があり、現行Desktopの利用可否は別途確認が必要。

## 2. 初回セットアップ・ローカルアカウント

### 2.1 セットアップ

- 初回セットアップを本体と別ウィンドウで開く。
- セットアップが必要な間は本体チャットの利用開始を保留する。
- ようこそ画面でα版・機能制限を案内する。
- 言語を選択する。候補は日本語・英語・韓国語・中国語・ポルトガル語。
- Windowsに合わせる/ライト/ダークを選択する。
- テーマ変更をセットアップ画面とネイティブ側へ即時反映する。
- ステップに対応した右側のアニメーション付きUIプレビュー。
- ステップ番号・現在位置・完了済みステップ表示。
- 戻る/次へ/開始の操作。
- 必要な入力や同意がそろうまで先へ進むボタンを無効化する。
- Tab/Shift+Tabによるセットアップ内のフォーカス移動制御。
- 接続先にOllama/OpenRouter/両方を選択する。
- 接続済み・設定済みの場合、接続設定の一部をスキップする。
- 既存の会話やプロンプトを保持したままセットアップを開き直す。
- Ollama未導入を検出し、公式入手先へ案内する。
- Ollama導入済み・停止中を区別して、起動を要求できる。
- Ollamaには接続できるがモデルがない状態を案内する。
- 導入済み会話モデルの一覧と選択。
- 接続/モデル状態の再確認。
- OpenRouterキーが保存済みかどうかを、値を表示せず確認する。
- ネイティブのAPIキー入力画面を開く。
- APIキー管理ページを開く。
- 規約とプライバシーポリシーを読む。
- ファイル・マイク・カメラ・位置情報・通信・常駐・更新の説明。
- 明示的な同意を記録して利用開始する。
- プライバシーの版が変わった場合の再同意。

### 2.2 PC診断・モデル導入

- Windows版・OSアーキテクチャの取得。
- CPU名・論理CPU数・物理コア数の表示。
- 総RAM・空きRAMの表示。
- GPU名・ドライバー情報の表示。
- 保存先の空きディスク容量の表示。
- Ollama版・API応答時間の表示。
- モデル保存先の目安と空き容量の表示。
- GPU等を十分に確認できない場合は診断の限界も表示する。
- ネットワーク接続の有無を表示する。全外部サービスへの到達成功とは区別する。
- RAM・空きRAM・CPUから保守的なローカルモデル候補を提案する。
- 推奨モデルの理由・容量目安・導入済みかを表示する。
- 推奨モデルの `ollama pull` コマンドをコピーする。
- Qwen 3.5の0.8B/2B/4B/9B候補をアプリからダウンロードする。
- すでにモデルがある場合は「他のAIモデルをダウンロード」と表示する。
- 導入済み/取得中の同モデルを重ねて取得しないためのボタン制御。
- 取得の待機中・実行中・完了・失敗・中断・キャンセル状態を表示する。
- ダウンロード量・全体量・進捗率を表示する。
- モデル取得の停止と再試行。
- 完了したモデルを一覧へ反映する。
- モデル取得は独立ワーカーで行い、本体を完全終了しても継続できる構造。
- 再起動後に取得状態を確認する。
- 追加ツールの検出と実行確認済みかを区別する。
- 「今このPCで何が使えるか」を状態一覧で表示する。ただし一部説明は古いので第15章参照。

### 2.3 このPCのアカウント

- 外部サービスとは別の、このPC用アカウント作成。
- 呼ばれたい名前の登録。
- 任意の4〜12桁数字PINの設定。
- PIN設定時の起動ロックと解除。
- PIN誤入力が続いた場合の30秒待機。
- ロック中の本体・Mini Chat・常駐経由のAI利用の制限。
- 生まれた年による年齢区分の確認。
- 年齢を答えない選択。
- 初回の注意事項確認。
- アカウント設定から呼び名を変更する。
- PINの設定・変更・解除。
- 生まれた年/年齢回答の変更。
- 今すぐロックする操作。
- 未成年区分の場合、検索のセーフサーチを強くする。
- 未成年向けの画像生成/会話の指示調整。
- ローカルアカウントは、会話データ全体を暗号化する機能や複数人の独立アカウント切替とは別。

## 3. AI接続・モデル・推論設定

### 3.1 接続先

- OllamaのローカルAPIへネイティブ側から接続する。
- Ollama導入済みモデルを一覧に取り込む。
- Ollamaのモデル情報・対応機能を取得する。
- OpenRouterを1つのキーで利用する。
- OpenAI公式APIへの直接接続。
- Anthropic公式APIへの直接接続。
- Gemini公式APIへの直接接続。
- ChatGPTのブラウザーサインイン経路。契約枠の認可が必要で、APIキー経路とは区別される。
- ChatGPTのサインイン中案内・キャンセル・サインインし直す・サインアウト。
- ChatGPTのサインイン済み/契約枠認可の状態表示。
- GPT系でChatGPT契約枠とAPIの利用経路を選ぶ設定。
- OpenAI互換のカスタムAPI接続先URL。
- キー不要の互換サーバーはURLだけで登録する。
- llama.cpp server/LM Studio/Jan/KoboldCpp等のローカル互換サーバーを登録する。
- よくあるローカルサーバーのポートを検出する。
- サーバーの名前・URL・有効/無効を管理する。
- サーバーの接続中/停止中と、取得できたモデル数を表示する。
- ローカルサーバー登録を削除する。
- 接続済みサービスを先に表示し、未設定のサービスを「接続を追加」にまとめる。
- プロバイダーの接続テストとチャット用モデル件数表示。
- APIキーの追加・変更・削除。
- APIキーはネイティブダイアログで入力し、Windows DPAPIで保存する。
- キーは通常表示しない。ネイティブ画面で確認操作をしたときだけ一時表示する。
- 接続先の解除時に確認する。
- Ollama停止・未導入モデル・認証・容量不足などの失敗を利用者向けの文言へ変換する。

### 3.2 モデル一覧と選択

- チャット用と画像生成用のモデル一覧を分ける。
- クラウドとローカルを、モデル選択画面の中で扱う。
- Ollamaの表示領域を設ける。
- 提供会社/プロバイダーごとに一覧をまとめる。
- プロバイダーの開閉。
- 選択中モデルをチェック表示する。
- 表示名と実モデルIDを扱い分ける。
- モデル名・ID・提供元の検索。
- 空白区切りの複数検索語で絞る。
- 「無料」「thinking」等の補助語を検索に使う。
- お気に入りモデルの先頭表示。
- お気に入りを設定から任意に追加/解除する。
- お気に入りはメーカー欄にも残す。
- 新着モデルのNEW表示と、お気に入り欄への優先表示。
- 各社の現行モデルを通常欄に表示する。
- 現在の通常表示上限は**1社10件**。あふれたものを「旧モデル・その他」に畳む。
- 旧モデルを展開して選ぶ。
- 選択中の旧モデルは見失わないよう通常側へ出す。
- 重複ID・日付付き重複スナップショット・一部別名や非会話モデルを整理する。
- OpenRouterでは主要提供会社を中心に絞る。
- 選択済み/お気に入りとして保持したモデルは、通常の整理で消さない扱いがある。
- 利用不可・劣化/障害状態のモデル表示。
- テキスト・画像・音声・動画・ファイル・ツール・Thinking対応を能力表示に使う。
- 入出力価格、無料か、有料かの表示。
- 高額モデル選択時の推定費用警告。
- 文脈長・モデル情報に応じた入力制限や送信経路の調整。
- 自動選択を実モデルとは別の項目として置く。
- 自動選択では用途・画像の有無・利用できる接続先・モデルの能力等を考慮する。
- 通常会話に向かない埋め込み/再ランキング等を自動選択の候補から除外する。
- 自動選択に関する旧Web版の「Jevを必ず使用」という前提は現行Desktopの機能として断定できない。Desktop側には規則ベース選択もある。

### 3.3 Thinking・生成設定

- モデルが対応する場合だけInstant/Thinkingを表示する。
- Thinking専用モデルはThinkingとして扱う。
- Thinking非対応モデルでは不要な設定を隠す。
- 対応する思考の深さをメーター/段階選択で変更する。
- メーターをクリック・ドラッグ・キーボードで操作する。
- モデルごとに思考の深さを保存する。
- 最小/低/中/高/極高/最大/Ultra等を、対応能力と経路に合わせて選ぶ。
- Ultraは表示上の別段階で、経路によりxhighや思考予算へ変換する。
- 思考設定の入口を画面上部か入力欄右側にする。
- Temperatureを対応モデルで調整する。
- Top Pを対応モデルで調整する。
- 新規チャットの既定モデルを設定する。
- キャラクター会話のモデルを別に選択する。
- プレイヤーのモデル/Thinking設定を通常チャットと分けて保持する。
- 画像生成のモデル/Thinking設定を別に保持する。
- ローカルAIのモデル保持時間を2分/10分/30分/アプリ使用中から選ぶ。
- 省メモリー/バランス/応答優先のプリセット。
- Mini Chatを開く、または入力を始める際のローカルモデル先読み。
- 全画面アプリを約30秒使っているとき、自アプリが読み込んだローカルモデルを解放する設定。
- 回答生成中は解放しない。
- 他アプリが読み込んだモデルを勝手に解放しないための対象管理。
- モデル保持設定は、モデル自体の推論品質や演算速度を変更する機能とは区別される。

### 3.4 モデル比較

- 同じ質問を複数モデルへ並列に送る。
- 初期状態で利用可能な2モデルを選ぶ。
- 比較するモデルを2～4個で設定する。
- 比較する列のモデルを変更する。
- 列を追加/削除する。
- 比較時のツールモードを選ぶ。
- 添付必須のツール等、比較に適さない選択肢を除く。
- 必要なツールの実行と外部送信を確認する。
- モデルごとの検索エンジン設定を利用する。
- 現在の比較はInstant指定で、通常チャットのThinking設定とは別。
- 各モデルの待機/生成/完了/中止/エラーを個別表示する。
- 各列へストリーミングで回答を表示する。
- ツール名/進行内容/所要時間を表示する。
- 生成画像を表示して開く。
- 出典リンクを表示する。
- 列ごとの回答をコピーする。
- 比較全体を停止する。
- 比較結果を消去する。
- 比較結果は通常チャット履歴へ自動保存しない一時的な状態。

## 4. チャット・スレッド・入力・回答操作

### 4.1 スレッドとナビゲーション

- 新規チャットを作る。
- 保存済みチャットを開く。
- 最後に開いていた会話IDを使った復元。
- チャット一覧を更新日時等に基づいて並べる。
- 今日/昨日/7日以内/30日以内/それ以前でグループ化する。
- タイトル・会話内容の検索。
- プロジェクトで一覧を絞る。
- プロジェクト未所属だけを表示する。
- スレッド名の変更。
- スレッドの複製。
- スレッド削除と確認。
- 1会話のJSON書き出し。
- 1会話のMarkdown書き出し。
- 通常/キャラクター会話をアイコン等で区別する。
- キャラクター一覧ではアバター・名前・直近メッセージ・日付/未読を表示する。
- 一時チャットを作る。
- 一時チャットは通常の保存履歴へ残さない。
- 一時チャットの状態を表示する。
- 会話途中から別スレッドへ分岐する。
- サイドバーを開閉する。
- チャット/数学/コーディングの表示を切り替える。
- プロジェクト・Music・ライブラリ・道具・アクティビティ・設定へ移動する。
- チャット内の検索バーで本文を探す。
- 検索一致箇所のハイライトと移動。

- 長いユーザーメッセージの折り畳み/展開。

### 4.2 入力欄

- ファイル選択から添付する。
- ドラッグ&ドロップで添付する。
- 貼り付けた画像等を添付する経路。
- 添付名・種類・サイズ・サムネイル等を表示する。
- 添付を押して内容をプレビューする。

- ＋メニューで今回使うツールを指定する。

- 指定済みツールをもう一度選ぶと自動へ戻す。
- 選択したツールをチップ等で確認する。

- 長押し音声入力と認識状態の表示。
- モデルや接続がない場合に、接続/モデル設定へ案内する。

### 4.3 会話生成・表示

- 会話履歴をモデルへ渡して文脈を継続する。
- 通常のシステムプロンプト・プロジェクト指示・メモリーを合成する。
- AIのストリーミング応答。
- ストリーミング文字のなめらかな表示。

- コード言語と行数を表示する。
- コードのシンタックスハイライト。
- 外部リンクの安全な開き方を制御する。
- チャット内の外部画像を勝手に読み込まず、許可された内部画像と分ける。
- 画像・音声・動画添付を、種類に応じてプレビューする。
- AI処理の待機・接続・生成・ツール実行状態を表示する。

- Thinking中は思考中の表示と、必要に応じた思考詳細を表示する。
- 思考フェーズごとの所要時間を表示する。

## 5. 検索・調査・天気・旅行・歌詞・画像生成

### 5.1 自動ツールと通常チャットのエージェント

- 初期のツール選択は自動ツール。
- 質問の内容から検索・天気・成果物・画面確認等を選ぶ補助ルーター。
- 「調べて」など短い依頼を、前のユーザー話題や直前の提案を使って補う。
- 現行AIモデルなど時点依存の話題を検索対象にする判定。
- 長い私的な貼り付けを、そのまま検索クエリにしない制御。
- 対応モデル・通常テキスト会話では、AI自身がツールを繰り返し使うエージェント経路。
- エージェントの最大8ステップ制御。
- ツール実行前の一言の途中報告。
- ツールの結果を受けて、追加検索やページ読み取りを判断する。
- 最終ステップはツールを増やさず回答する。
- 途中報告と同じ文を最終回答で重複させないための処理。
- エージェントが呼べるWeb検索。
- エージェントが呼べるページ本文読み取り。
- エージェントが呼べる動画URL解析。
- エージェントが呼べる道具カード表示。
- 有効にしたMCPサーバーのツールを通常チャットでも使う。
- 添付付き等は同じエージェント経路ではなく、通常のマルチモーダル経路等へ分ける。
- キャラクター/音声など、会話の性質が違う経路では従来の制御を残す。

### 5.2 Web検索・ページ読み取り

- SearXNGによる独自検索。
- 自分で運用するSearXNG URLの登録・保存・解除。
- SearXNG接続テストと結果件数の表示。
- JSON出力が無効なSearXNGに対する案内。
- ローカル/家庭内等はHTTP、インターネット上はHTTPSを要求するURL検証。
- SearXNG設定済みならDuckDuckGoへ検索語を送らない。
- SearXNG未設定時だけDuckDuckGoを使う明示オプトイン。
- 検索未設定の失敗画面から、送り先を確認してDuckDuckGoを有効にし再試行する入口。
- モデル内蔵検索に対応する場合、独自検索と内蔵検索をモデル別に選ぶ。
- 内蔵検索の課金表示。
- 検索語だけを外へ送るための長さ/形式検証。
- 最新/今日/今年等の依頼に応じた期間指定。
- day/week/month/year/anyの検索鮮度指定。
- 期間指定で結果がなければ期間なしで再検索する。
- 日付がある結果を新しい順に扱う補助。
- 結果のタイトル・URL・抜粋・公開日をAIへ渡す。
- URL先の本文を取得する。
- Shift_JIS等の日本語ページの文字コード処理。
- 長いページから、質問やfocusに関連した段落を選ぶ。
- 最新を聞く場合、最近の日付を含む見出し/段落を重視する。
- 読み取り失敗時、Common Crawl保存コピーから本文取得を試みる。
- 保存コピーの取得日を明示する。
- 私設ネットワークや秘密情報を含むURLをアーカイブ照会から除外する。
- 危険なURL・内部アドレス等を制限する読み取り経路。
- 出典の参照番号と出典一覧。
- 出典のタイトル・サイト・抜粋・日付・確認情報を表示する。
- 本文中の出典番号から根拠を確認する。
- 根拠の小窓/詳細画面の開閉。
- 根拠画面を常時全面にせず、必要なときに開く。
- サイトアイコンを専用経路で扱う。

### 5.3 ローカルSearXNGのかんたん設定【追加導入条件付き】

- アプリ内から、このPC専用SearXNGの準備を開始する。
- Python環境を使い、公式GitHub/PyPIから必要物を取得する。
- アプリのデータ領域内へ専用環境を配置する。
- 127.0.0.1だけで待ち受ける構成。
- 未導入/準備中/停止中/稼働中を表示する。
- 準備段階・進捗・経過時間・詳細ログ・エラー表示。
- 設定画面を閉じても準備を継続する。
- 導入済みSearXNGの起動・停止。
- 入れ直しと削除時の確認。
- ローカルSearXNGを検索先として使用しているか表示する。
- アプリ起動に合わせた導入済み検索環境の起動処理。

### 5.4 Deep Research

- 調査テーマを入力する。
- 調査前に計画を確認する。
- 目的・確認したい論点・優先サイトを編集する。
- 計画を戻してテーマからやり直す。
- 計画を承認してジョブを開始する。
- 調査の待機/実行/一時停止/完了/失敗/中止状態。
- 複数検索とページ本文の確認。
- 現行UIの枠は最大3検索・30情報源・3本文読み取り。
- 検索数・情報源数・本文取得数の表示。
- 保存したチェックポイントから再開する。
- 調査の一時停止・再開・中止。
- 途中で優先事項を追加し、調査の方向を変える。
- 根拠付きレポートと品質情報の保存。
- 調査履歴を一覧表示する。
- 保存レポートを取得し、チャットで続ける。
- 調査履歴を削除する。
- 長くかかるジョブでも、パネルを閉じて別の操作をする構成。
- 旧アクティビティの「定期調査」とは別。自動化の現行入口は第13章。

### 5.5 天気

- 地域名を解決して天気APIへ問い合わせる。
- 「東京」等が見つからない場合、地名の言い換えを試す。
- 現在地の座標を使う天気取得。
- 送信する座標を約1km単位へ丸める処理。
- 現在の天気・気温・体感温度。
- 降水量・湿度・風向・風速・最大瞬間風速。
- 時間別予報。
- 日別予報。
- 紫外線等の予報データ。
- 危険な暑さ/強い突風/大雨/強い紫外線/雷雨の目安表示。
- 注意表示は天気数値から作る目安で、公式防災警報の代替ではない。
- 更新時刻・解決した地名・座標の表示。
- Open-Meteoとライセンスのクレジット。
- ローカルモデルへ渡す時間別情報を短くまとめる処理。
- 天気に応じた挨拶を任意で使う。

### 5.6 旅行・経路

- 旅行プランナーモード。
- 目的地/出発地/日数等をもとに検索とAIで日程を作る。
- 日ごとの時刻付き予定をカード表示する。
- 各予定の場所を地図検索リンクで開く。
- 持ち物・注意・代替案・予約や事前確認事項を表示する。
- 参照した情報源と確認時刻/警告を付ける。
- Desktopの旅行生成は、未検証の料金や予約確認を事実扱いしないため、予算等を落とし `verified=false` にする処理がある。
- 高度な乗換・リアルタイム運行・複数経路の表示コンポーネントは残るが、その全項目が現行Desktopで生成されるとは限らない。

### 5.7 チャットの歌詞検索

- 曲名やアーティスト名から歌詞/楽曲情報を探す。
- Web掲載先、ローカル歌詞、歌詞DB等の区別。
- 曲名・アーティスト・アルバム・時間・ジャンル・リリース情報のカード。
- 一致度や取得元情報を表示する。
- 歌詞掲載先/楽曲ページへのリンク。
- 外部サービスが試聴音源を提供する場合のサンプル再生・一時停止・シーク・再試行。
- 試聴音源がない場合に未提供と表示する。
- Musicの全画面同期歌詞とは別の表示。
- 全歌詞を自由に転載することを保証する機能ではなく、外部掲載先・取得元・著作物の扱いに制限がある。

### 5.8 画像生成【対応外部モデル・キー等が必要】

- 文章から画像を生成する。
- 画像生成専用のモデル選択。
- 参照画像を添付して生成/変更依頼を送る。
- 前の生成画像を次の変更依頼の参照に使う。
- 直前までの変更依頼も渡し、人物/構図/変更不要部分の維持を指示する。
- モデルの参照画像枚数上限を検査する。
- 前の生成画像と新しい添付を合わせた枚数を検査する。
- 参照画像の合計サイズを検査する。
- 画像入力非対応モデルへの参照画像送信を拒否する。
- 生成中/成功/失敗の状態表示。
- 生成画像のチャット内サムネイル。
- 画像を拡大して表示する。
- 縮小・拡大・100%へ戻す。
- ダブルクリックによる表示倍率切り替え。
- 生成画像を保存する。
- 生成画像をライブラリにまとめる。
- 対応モデルで画像生成のInstant/Thinking/エフォートを設定する。
- 対応OpenAI画像モデルではLow指定、その他は提供元既定値という設定表示。未成年向け制御は別途適用される。
- 同一人物や完全な構図維持を保証する機能ではなく、参照画像と文脈を維持してモデルへ依頼する仕組み。

## 6. ファイル・ライブラリ・プロジェクト・メモリー

### 6.1 添付と文書読み取り

- テキスト: txt/md/json/csv/html/css/js/ts/tsx/jsx/py/xml/yaml/yml/log。
- 文書: PDF/DOCX/XLSX/PPTX/ODT/ODS/ODP/RTF。

- 音声: MP3/WAV/M4A/OGG/WebM/FLAC/AAC等。
- 動画: MP4/WebM/MOV/MKV/M4V等。
- 拡張子とMIMEから種類を判定する。
- 非対応形式と疑わしいバイナリテキストを拒否する。
- テキスト2MB・文書24MB・メディア256MB等の読み込み上限。送信経路の上限はこれと別。
- 長すぎる抽出本文を制限し、警告する。
- 画像の縮小と、詳細を読みやすくする画像分割処理。
- ローカル動画添付からフレームを抽出して画像対応モデルへ渡す。
- テキストの内容プレビュー。
- 画像プレビュー。
- 音声/動画の再生プレビュー。
- PDFのページ表示・ページ移動・拡大率変更。
- Word等の本文プレビュー。
- Excel等のシート/表プレビュー。
- プレゼン文書の抽出情報プレビュー。
- PDFのテキスト抽出。画像だけのPDFに対する万能OCRとは別。
- ファイル内容を入力欄へ挿入する。
- ファイルを要約する依頼。
- 問題点を探す依頼。
- コード改善を依頼する。
- Codex向け指示へ整理する依頼。
- 保存済み添付を再度チャットへ追加する。
- 添付の実データを必要になった時に読み込む。
- 保存済みメディアのプレビュー用URLを管理する。
- Office等の圧縮文書について、容量や内容の形式検証を行う。
- 旧バイナリOffice形式（doc/xls/ppt）は現行の読込対象とは別。
- 音声ファイルを添付できることと、選択したAIが音声を直接理解できることは別。

### 6.2 統合ライブラリと検索

- ピン留め回答の本文を入力欄へ戻す。
- ピン留め回答をコピーする。
- ライブラリからピン留めを解除する。
- 成果物の作業画面を開く。
- 添付を次のメッセージへ追加する。
- 生成画像のサムネイル一覧。
- 音声メモへの入口。
- プロンプトライブラリへの入口。
- メモリー管理への入口。
- メディア作業空間への入口。
- メディア作業空間でファイル名・種類による検索。

- 添付あり/画面あり/画像ありによる検索フィルター。

### 6.3 プロジェクト

- プロジェクトの作成・名前変更・削除。
- プロジェクトの色設定。
- 利用者用説明メモ。AIへ自動送信する指示とは区別する。

- 記録から元の会話を開く。
- 記録を削除する。
- AI回答から「プロジェクトに残す」提案を表示する。

### 8.2 読み取り・編集ツール

- `list_files`: 作業先内のファイル/フォルダー列挙。
- 深さ指定、依存/生成フォルダーを除いた列挙。
- `read_file`: 行番号付きのテキスト読み取り。
- 開始/終了行を指定して大きなファイルを部分読みする。
- `search`: ファイル内容検索。
- 検索先・glob・正規表現・前後文脈を指定する。
- `glob`: 名前パターンでファイルを探す。
- `outline`: 関数・クラス・メソッド等の概要と行番号を調べる。
- プロジェクト構成・使用言語・ビルド方式等の把握を補助する。
- `write_file`: 新規作成または全文置換。
- `edit_file`: 既存文字列の置換。
- 置換対象が一意か、まとめて置換するかを検査する。
- `multi_edit`: 複数編集をまとめて扱う。
- 編集前に読んだか・読んだ後に更新されていないかの確認。
- 利用者や別プロセスの変更との競合を検出する処理。
- `delete_file`: Windowsごみ箱への移動。
- `update_plan`: 手順の作成・pending/in_progress/completed更新。
- ファイル数・読込量・検索件数・結果文字数等の上限。
- ツール引数が不正なとき、AIへ修正可能なエラーとして返す。

### 8.3 コマンド・実行・ブラウザー

- `run_command`: 作業先のPowerShellコマンド実行。
- コマンドごとの作業ディレクトリ指定。
- 実行時間上限の指定。
- 標準出力・終了コード・タイムアウト・切り詰め表示。
- `start_process`: 開発サーバーや監視等の長時間プロセスを起動する。
- `read_process`: 実行中プロセスのログと状態を読む。
- `stop_process`: 起動したプロセスを止める。
- ログに出たローカルURLを検出する。
- `open_path`: 生成したファイルを既定アプリで開く。
- `preview_file`: フォルダー内のHTMLを相対CSS/JS/画像付きでプレビューする。
- `web_search`: ドキュメント・エラー・仕様等を調べる。
- `generate_image`: 承認した画像生成を作業フォルダーの画像として保存する。【対応接続・費用条件付き】
- `browser_open`: ブラウザーペインへURLを開く。
- `browser_snapshot`: ページタイトル・URL・可視テキスト・番号付き操作要素を読む。
- `browser_click`: 直近スナップショットの要素番号でクリックする。
- `browser_type`: 要素番号で入力する。
- `browser_scroll`: 上下・先頭・末尾へスクロールする。
- `browser_back`: 前のページへ戻る。
- AIブラウザーへの認証情報入力を制限する。
- 利用者もブラウザーペインを直接操作できる。
- ブラウザーの複数タブ。現行UI上限8タブ。
- タブの追加・切替・閉じる・Deleteによるタブ閉じ。
- URL入力・戻る・進む・再読み込み。
- 既定ブラウザーで開く。
- 開発サーバーの準備待ち表示と、待つのをやめる操作。
- ページ表示失敗時の再試行。

### 8.4 承認・安全・復元

- 変更前ファイルのチェックポイント。
- 作業単位のUndo。
- Undo時に対象がさらに変更されていないか確認する処理。
- 削除を含む変更を復旧対象として記録する。
- 承認・拒否・一時許可等の履歴。
- 許可履歴の検索/確認・削除操作。
- 「作業用分岐」で元フォルダーのコピー内を編集する。

- 分岐側の変更ファイルを一覧表示する。

## 15. 未接続・制限・資料と実装の差

### 15.1 「存在するが利用可能とは数えない」もの

| 項目 | 現状の区別 |
|---|---|
| 通常チャットのプロバイダー別音声通話 | UI側の実装はあるが、Desktopで対応する通話処理を確認できない。通常の音声入力やVOICEVOX読み上げとは別で、通話を完成済みとしない |
| キャラクター音声クローン・通話 | Desktop側で利用不可として扱われている。音声クローンから実通話まで利用できるとは数えない |
| チャットの一般音声分離画面 | 旧UIが残るが、そのAPI経路がDesktopにつながっているとは確認できない。Music専用カラオケの分離処理とは別 |
| 汎用capabilitiesの動画・音声ツール判定 | Desktop互換応答にはffmpeg/ffprobe/Demucs/yt-dlpをfalseにする部分がある。専用Music/Player処理まで全て未実装という意味ではないが、旧UIで隠れる可能性がある |
| Activity内の旧「定期調査」 | 開発中扱いの経路が残る。道具箱の実装済み「自動実行」と混同しない |
| アカウントのクラウド同期・複数端末同期 | 現在のローカルアカウントと同一ではない。同期の準備済み表示にはなっていない |
| 完全な自動更新インストール | 新版確認・配布ページ案内はあるが、無操作のダウンロード/インストール/再起動まで完成済みとはしない |
| 完全な全データ移行バックアップ | UIの選択対象以外の巨大メディア・モデル・秘密情報等まで、一式復元できるとは確認していない |
| 旅行のリアルタイム運賃等 | 表示コンポーネントと、検証済みの現在情報は別。取得していない情報を確定データとして扱わない |
| 全モデルでの音声・映像直接入力 | モデルと転送経路に依存する。静止フレームによるPlayer解析は、音声までネイティブ入力できることを意味しない |
| OmniMediaPlayerとの完全な機能一致 | ベースにした構成・一部機能はあるが、同ソフトの全機能が復元されたという保証はない |
| macOS/Linux版 | 共通処理を分離した構造だが、今回の対象はWindows。各OS版の完成を意味しない |

### 15.2 実装と利用条件の境界

- ローカルAIには導入済みモデル・稼働中のエンジン・十分なPC資源が必要。
- クラウドAIには各接続方式の認証・契約・残高・モデルの提供が必要。
- モデル一覧は供給元の変更で変わるため、特定のモデルが常に使える保証はない。
- Thinking/画像入力/ツール/構造化出力等の対応はモデルごとに異なる。
- モデルのメタデータによる対応判定と、実際のモデル応答の正しさは別。
- Web検索は設定した検索先の稼働・利用条件に依存する。

- Spotifyの接続は、利用者がアプリ登録や認可を整える必要がある。
- AI解析は画像サンプルや抽出本文に基づくため、元の全情報を理解した保証ではない。
